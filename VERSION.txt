v00.00.09i3 - Compile / Unity 6.6 compatibility fix
- Fixes CS0117 in PrototypeSoldierVisualPass09I where CreateDenmarkDefault() and CreatePrussiaDefault() were referenced but not defined by PrototypeUniformProfile09H.
- PrototypeUniformProfile09H now exposes CreateDenmarkDefault() and CreatePrussiaDefault() as thin compatibility wrappers over the existing CreateFactionDefault(BattleTeam) implementation, so faction defaults remain centralized and cannot drift.
- PrototypeNavigationRecoveryManager now uses Unity 6.6 Object.FindObjectsByType<Transform>() instead of the deprecated FindObjectsSortMode overload.
- No movement parameters, combat rules, route semantics, visual sizing, uniform colours or AI behaviour are changed by 09i3.

v00.00.09i2 - Tactical readability pass
- QA screenshot showed that the first 09i graphics pass was not visually strong enough at ordinary tactical zoom: infantry still read as dark sticks and standards were too small to carry regiment identity.
- PrototypeSoldierVisualPass09I remains presentation-only but increases base torso/limb/head/rifle silhouette size without changing any Regiment formation slot or BoxCollider footprint.
- Small uniform/equipment details remain visible out to approximately 285 m instead of disappearing around 135 m.
- Soldier render rigs receive bounded distance-based visual scaling from about 1.04x close to about 1.24x at long tactical distance. This scales each render rig around its existing formation slot only; unit spacing, destination and collision remain unchanged.
- Headgear, rifles/bayonets, hands, boots, straps, cartridge boxes and packs receive modest readability increases.
- New PrototypeVisualReadability09I2 dynamically enlarges the procedural 09i regimental standard from roughly 1.18x at close range up to roughly 1.52x at long tactical range.
- VIS-09I2 telemetry explicitly reports whether each procedural 09i standard is found. This makes a failed visual-layer install obvious instead of silently falling back to the 09g look.
- Expected startup telemetry: SOLDIER-09I2, STANDARD-09I and VIS-09I2.
- 09i2 remains rendering-only and does not alter movement, combat, morale, cohesion, Officer AI, player routes or selection.

v00.00.09i1 - V3 hard-obstacle detour continuation fix
- QA log from a direct player-controlled AI-OFF group move confirmed 1. Regiment can enter a repeat loop around a Farmhouse.
- The captured log contains thousands of repeated NAV-V3 Detour=True entries for the same Farmhouse centre and the same detour point.
- Root cause: after reaching the first detour point, the same hard obstacle can still block the final route. Base V3 finishes the reached detour leg and can immediately select the same/near-identical point again instead of continuing around the obstacle.
- 09h4 manual route recovery correctly detected no progress and inserted a bypass, but V3 route sanitisation/goal adjustment could move that bypass and the base detour loop could resume.
- PrototypeNavigationV3DetourContinuation09I1 runs immediately after base V3 and only acts when V3 is already in a Farmhouse/Barn detour and the current detour point has effectively been reached while the real goal is still distant.
- The layer chooses a new safe continuation point around the SAME active hard obstacle, validates the local leg with V3 Column navigation/path penalties, rejects local river-crossing candidates, and writes the continuation back into V3's existing NavigationState.
- Navigation V3 remains the steering owner. The continuation layer does not teleport the regiment and does not create an independent pathfinding authority.
- Continuation legs are bounded to 10 per active obstacle and emit explicit NAV-V3-09I1 telemetry.
- Expected success telemetry: NAV-V3-09I1|Unit=...|Continuation=True|Obstacle=Farmhouse|FromVia=...|NextVia=...
- This fix applies to Farmhouse and Barn hard obstacles; decorative trees and individual FencePosts remain soft/pass-through from 09h4.

v00.00.09i - Soldier Visual Pass 2 / Big Graphics Buff
- PrototypeSoldierVisualPass09I hides legacy primitive soldier renderers and rebuilds each representative infantry figure as a lightweight articulated procedural rig.
- Improved human proportions: tapered torso, coat skirts, separate legs, boots, arms, hands, neck/head and faction-specific headgear.
- Danish infantry receive cap/visor/band silhouette; Prussian infantry receive Pickelhaube dome/band/spike/visor silhouette.
- Equipment: backpack, crossed straps, cartridge box, optional canteen, improved rifle stock/barrel/bayonet and metal/wood material separation.
- Officer representative receives sash, shoulder boards and sword.
- Standard-bearer representative receives sash/pole grip and carries no rifle.
- Six deterministic visual variants reduce exact cloned appearance.
- Cosmetic march arm/leg swing, ready pose and brief firing pose are driven from existing state only.
- Uniform Designer remains authoritative for per-regiment colours.

v00.00.09i - Regimental Standard Visual Pass 2
- PrototypeRegimentalStandards09I hides the old 09g QA standard renderers while retaining the underlying rollback/reference code.
- Each regiment receives a procedural two-sided cloth mesh with wind deformation, pole, ferrule, spear finial, cords, animated ribbons and fringe.

- Standards remain presentation-only with no morale/combat effect.
