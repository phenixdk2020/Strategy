v00.00.09h4 - Manual movement correction
- User clarified the stuck regiment was under direct player control with Officer AI disabled. Therefore the earlier AI frontage diagnosis does NOT explain that specific stuck observation.
- Manual movement path is treated separately from AI frontage: PlayerCommander route -> Regiment OrderMove -> Navigation V3 steering.
- PrototypeManualRouteRecovery09H4 monitors active PlayerCommander routes only when Officer AI is OFF.
- Manual routes march in Column while more than 14 m from the current route waypoint and deploy to the route's final formation near destination.
- If a manual route makes less than 0.45 m useful movement for 3.5 seconds while still more than 5 m from the waypoint, a controlled bypass waypoint is inserted into the existing PlayerCommander route.
- Bypass candidates are evaluated with Navigation V3 column validity/path penalty; river-crossing bypasses are rejected.
- Recovery is bounded to four inserted bypass waypoints per active route and has a 4-second cooldown to avoid oscillation.
- New telemetry: MANUAL-ROUTE-09H4 and MANUAL-FORMATION-09H4.
- Navigation V3 remains the sole local steering owner. 09h4 changes higher-level route waypoints/formation only when a manual route is demonstrably stalled.

v00.00.09h4 - Fence soft-pass-through correction
- Screenshot geometry showed manual order paths intersecting rows of visual FencePost objects.
- Previous V3 obstacle semantics treated every FencePost as a hard circular obstacle. Closely spaced posts could therefore combine into an effectively continuous invisible wall for a formation centre/clearance.
- Individual FencePost objects are now soft/pass-through in the current prototype, matching the existing decorative-tree pass-through rule.
- Buildings/barns remain hard discrete obstacles; river/water remains bridge-only.
- Fence effects can later return as area/segment-based movement/cohesion penalties rather than one hard navigation circle per visual post.
- Soft-obstacle telemetry: NAV-SOFT-09H4.

v00.00.09h3 - March column / deployment formation fix
- 09h3 addresses AI-controlled approach formation only.
- PrototypeApproachFormationPolicy09H3 executes only when Officer AI is enabled.
- AI regiments with an active destination march in Column while outside the deployment zone.
- For attack missions the deployment zone begins at approximately EffectiveRange + 12 m from the nearest enemy.
- For MoveToPoint missions the unit remains in Column while destination distance is greater than 16 m and the nearest enemy is still outside effective range.
- Once inside the deployment zone the policy stops overriding formation, allowing Officer AI/frontage to deploy the regiment to Line.
- Player-controlled/manual units with Officer AI disabled are intentionally not handled by 09h3; 09h4 now provides the manual route formation policy.
- New telemetry prefix: FORMATION-09H3.
- AI-SPACING-V3 LegacyPlannerDisabled=True is expected and is not an error.

v00.00.09h2 - Attack frontage stability fix
- 09h2 remains valid for AI-controlled multi-regiment attacks, but it is not the explanation for the later clarified manual AI-OFF stuck case.
- Frontage slots are sticky once allocated.
- A slot is reconsidered only when blocked/conflicted, target moved materially, or an AI frontage regiment makes no meaningful progress for 3.5 seconds.
- No-progress recovery tries an alternate slot instead of reissuing the same failed destination.
- Attack target selection uses hysteresis to reduce target churn.
- Telemetry prefix: AI-SPACING-V3.
- PrototypeMovementStallDiagnostics09H2 remains passive/read-only and reports sustained active-destination stalls through STALL-09H2.
